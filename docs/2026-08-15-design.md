# Category Autofill 插件设计文档

- 日期：2026-08-15
- 状态：已与用户确认
- 插件名称：Category Autofill（ID：`category-autofill`）

## 1. 目标

自动把笔记 frontmatter 中的 `category` 属性填充为该文件**直接父文件夹**的名称，保持分类与目录结构一致。

## 2. 已确认的需求决策

| 问题 | 决策 |
| --- | --- |
| 触发时机 | 自动监听 + 手动命令（两者都要） |
| 已有 category 值 | 做成设置项「覆盖已有值」，默认开启 |
| 多层子文件夹 | 只取直接父文件夹名（如 `技术分享/前端/x.md` → `category: 前端`） |
| 库根目录文件 | 跳过不处理 |

## 3. 方案选择

- **方案 A（选定）**：官方 API。用 `fileManager.processFrontMatter()` 读写 frontmatter，监听 `vault` 的 `create` / `rename` 事件实时更新，另提供全库批量命令。YAML 解析/写回全部交给官方 API。
- 方案 B（否决）：手写正则解析 YAML。引号、转义、多行值、无 frontmatter 文件等边缘情况极易出 bug，且绕过 Obsidian 元数据缓存。
- 方案 C（否决）：引入第三方 YAML 库做文件级修改。仍需自己写文件和刷缓存，且增加运行时依赖。

## 4. 架构

单文件插件（`main.ts`，预计 300 行以内）+ esbuild 构建（官方示例模板同款结构），零运行时第三方依赖。

```
obsidian-category-autofill/
├── main.ts              # 插件全部逻辑
├── manifest.json        # 插件清单
├── versions.json        # 版本兼容表
├── esbuild.config.mjs   # 构建脚本
├── package.json
├── tsconfig.json
├── .gitignore           # node_modules/、main.js（构建产物）
└── docs/                # 本文档
```

构建产物为 `main.js`，与 `manifest.json` 一起拷入用户库的 `.obsidian/plugins/category-autofill/` 即完成安装。

## 5. 核心逻辑

### 5.1 路径判定（纯函数，与 Obsidian API 解耦）

- `getParentFolderName(file)`：取 `file.parent.name`；`file.parent.isRoot()` 时为 null（根目录文件跳过）。
- `isInHiddenFolder(path)`：路径任一段以 `.` 开头（覆盖 `.obsidian`、`.trash`、`.git` 等）则跳过。
- 仅处理 Markdown 文件（`extension === "md"`）。

### 5.2 写入规则（唯一的写入入口，事件与批量命令共用）

`updateCategory(file)`：

1. 命中 5.1 任一跳过规则 → 返回「跳过」。
2. 计算目标值 = 直接父文件夹名。
3. 调 `fileManager.processFrontMatter(file, fm => ...)`：
   - 设置「覆盖」开启 → `fm.category = 目标值`；
   - 设置「覆盖」关闭 → 仅当 category 缺失、为空字符串、null 或空数组时填充；
   - category 已等于目标值 → 不写入（避免无意义改动与同步噪音）。
4. 每个文件独立 try/catch，失败计入失败数，不影响其他文件。

## 6. 自动监听

- `vault.on("create")`：新建 md 文件 → 立即填充；新建文件夹 → 忽略。
- `vault.on("rename")`：文件移动/改名 → 更新该文件；文件夹重命名 → 扫描新路径下所有 md 文件逐个更新（其父文件夹名已变）。
- 防抖去重：同一路径 200ms 内的重复事件合并处理，处理完从队列移除（无内存泄漏）。快速拖动大量文件不会重复写入。
- 插件不监听 `delete`、不监听 `modify`（`processFrontMatter` 写盘会触发 `modify` 事件，但因未监听所以不会形成循环）。

## 7. 手动命令

命令「自动填充 category（全库）」：遍历 `vault.getMarkdownFiles()`，逐个走 `updateCategory`，结束后 Notice 显示「更新 X 个 / 跳过 Y 个 / 失败 Z 个」。命令幂等，可重复执行。

## 8. 设置页

单个开关：「覆盖已有的 category 值」，默认开启。中文文案。

v1 不做（YAGNI，以后可加）：自定义排除文件夹列表、自定义属性名、完整路径模式。

## 9. 错误处理

- 逐文件 try/catch，批量命令汇总失败数并 Notice 提示。
- 无 frontmatter 的文件由 `processFrontMatter` 自动创建 frontmatter（实现时验证此行为；若官方不支持则改为「无 frontmatter 时用文本拼接方式创建」，逻辑仍收敛在本函数内）。
- 已知边界：文件在编辑器中有未保存改动时，`processFrontMatter` 写盘会触发编辑器重载、丢失未保存的正文改动。这是官方 API 的通用行为，在 README 中说明，不做规避（事件触发场景下几乎不会发生）。

## 10. 验证

- 静态验证：`tsc --noEmit` 类型检查 + esbuild 构建通过 + 代码审查（零运行时依赖，逻辑集中在 3 个函数）。
- 动态验证：无法在开发环境运行 Obsidian 桌面端，交付安装说明 + 验收清单，由用户在真实库中逐项测试。

验收清单：

1. 在子文件夹新建 md 文件 → category 自动填为文件夹名。
2. 把文件拖到另一个文件夹 → category 变为新文件夹名。
3. 重命名文件夹 → 其下所有文件的 category 变为新文件夹名。
4. 执行全库命令 → 历史文件被批量修复，Notice 计数正确。
5. 关闭「覆盖已有值」后手动填一个 category → 再移动文件，手动值不被覆盖。
6. 库根目录文件、隐藏文件夹（`.obsidian` 等）内文件 → 均不被改动。
7. category 已等于文件夹名 → 文件内容无任何改动。
8. 非 md 文件（图片、PDF）→ 不被改动。
